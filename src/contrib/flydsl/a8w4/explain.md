# 讲解代码
首先收集足够的信息：
 - 阅读目标源码文件
 - 查找调用该文件中对外函数API的其他文件（可能是上一级组件或者是测试用例），搜集使用方法
 - 查找目录下引用到目标源码文件的任何文档并阅读，了解设计过程，参考文献，实测性能等信息

通过文档+源码，按照逐渐细节化，自顶向下的顺序生成一份跟源码同名但是以`.explain`结尾的文件夹，其中包含一个README.md作为主要讲解文件，以及用于辅助说明的svg图像等附件。

# 功能描述
描述代码最主要的功能，配合调用方示例代码，描述代码对外提供的API的详细接口和含义，包括每个参数的含义，列表说明。

# 实现原理
这一节不使用源码来描述实现方法：
 - 使用paper中常见的，描述+伪码+示意图形式讲解实现的基本原理，如果是kernel代码，要着重说明任务如何在CTA间分配，每个CTA中的waves如何协作完成任务；
 - 对其中遇到的背景知识+不常见术语等给出简要的列表说明；

 - 对其中的一些设计选择给出基于事实的解释或者合理猜测；

# 代码细节

 - 代码按照逻辑分为段落章节讲解；
 - 辅助函数使用单独章节讲清楚功能，入参，返回值含义，内部实现基本原理；
 - 复杂而且冗长的主函数按照逻辑划分段落，每个段落使用下面的方式讲解：
   - 源码嵌入到文档中，但是在合适的地方（行尾或者单独起一行或者多行）加入醒目的注释，实时解释关键点
   - 遇到比较复杂的逻辑还要配合图像给与说明，包括：
    - 遇到特殊指令
    - 遇到跨lane交换数据
    - 遇到加载数据
   - 加载数据涉及到寄存器/LDS数据layout的，如果layout映射到原始tensor中比较复杂，不是简单的线性连续，一定要配图说明各个lane/thread的分布

# 总结回顾
 - 原理方面：
  - 如果某个设计选择背后有数学原理，此处给出稍微详细一点的说明或者搜索关键字；
  - 如果存在其他常见的替代做法也给与提及（可以搜索网络），开阔阅读者的眼界；
 - 细节方面：
  - 对于源码中做的好的部分和不好的部分给与专门提及；
  - 对于源码中可复用组件给与提及
