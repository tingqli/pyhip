## 实验 1：EP gemm 配置扫描（experiments/20261114_ep_cfg_sweep/）
在 l128 / m64 基础上改 gemm 参数（g2 nw / no / arb / sch，g1 sch / tr，sst），tokens=1024/3072/12288，冷 cache，3 轮交错取最小。
结果见 result.txt：

| 变体 | 1024 | 3072 | 12288 |
|---|---|---|---|
| l128 (基线) | 193.8 | 344.7 | 1058.0 |
| g2 nw=4 | 197.3 | 348.9 | 1064.2 |
| g2 no=128 | 204.8 | 369.3 | 1142.9 |
| g2 arb=64 / 256 | 不支持（arb 只能 (128)/越界 LDS） | | |
| g2 sch=1 / 2 | 196.6 / 195.4 | 346.4 / 347.0 | 1059.4 / 1054.4 |
| g1 sch=2 | 197.2 | 344.4 | 1050.0 |
| g1 无 TR | 195.2 | 343.0 | 1058.2 |
| sst=False | 194.8 | 349.6 | 1059.7 |
| m64 | 193.8 | 407.3 | 1276.1 |

结论：无变体超出 ±1% 的噪声，当前 CFGS 已在这些维度的局部最优；g2 no=128 明显更差（+6–8%）。无需修改调优表。

## 反思与建议
- 参数层面已无收益，剩余空间在结构：大 batch 的 gemm2（W 解码经 LDS 共享、更大 M tile）、小 batch 的固定开销（TP prep 合并、gemm1 split-K）——见 README 第 11 节。
- 没有发现值得替换当前 kernel 的外部实现；建议下一步按 11 节做「gemm2 重写」原型，并逐个核对 aiter/humming 的 open PR。
- 注意：同一配置在不同运行间可差 ~15%（12288：tune verify 911 us，本次 1058 us，由路由抽样/功耗状态引起），对比务必同进程交错测量。
